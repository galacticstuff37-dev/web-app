# Проверочные стенды

Три страницы, которые гоняют приложение **в настоящем Safari на устройстве** и
печатают отчёт текстом — его видно на скриншоте симулятора. Появились потому,
что Chrome с эмуляцией устройства **не воспроизвёл** главный дефект вёрстки
(прыжок на 48px после загрузки): его показал только полноэкранный Safari.

| Файл | Что проверяет |
|---|---|
| `tapcheck.html` | Онбординг целиком, обе ветки: кнопка на каждом шаге, видимый выбор, ZIP, лимит бесплатного плана, мнимые чекбоксы, сессия после перезагрузки |
| `authcheck.html` | Вход: ссылка с лендинга, настоящий Google (ссылка строится, PKCE, без демо-аккаунта), отсутствие Apple, почта и код, аккаунт в настройках, подтверждение удаления. Отдельные разделы про вошедшего человека: сессия пишется в localStorage синтетической (настоящую без Google не достать — анонимный вход выключен), и на ней проверяются подхват аккаунта, мина `hg.authNext` и разница между умершей сессией и нарочным выходом. Плюс раздел про то, что онбординг не выпускает в приложение без аккаунта: «I’ll pick my own» на preview уводила в библиотеку как в экран приложения, и человек оказывался внутри, минуя Save. И синхронизация: id строк, сценарии слияния (`__syncAudit`), полный no-op без сессии, анонимная запись отбита RLS |
| `synccheck.html` | Сквозная синхронизация на ЖИВОЙ базе — единственный стенд, которому нужен вошедший человек (сессия берётся из того же браузера, значит того же origin). Без параметров только читает: состояние, снимок отправки, содержимое базы, сходимость двух проходов. `?write=1` добавляет круг в обе стороны — правку «с другого устройства» прямо в Postgres и правку отсюда; **пишет в настоящий аккаунт**, поэтому по умолчанию выключено |
| `sweep2.html` | Вёрстка: 32 экрана × 5 состояний данных × 6 ширин = 960 рендеров. Ищет выходы за экран и ошибки консоли |

## Как запускать

Стендам нужен HTTP того же origin, что и приложение — они держат его в iframe и
читают его DOM. Мало того: собранный бандл ссылается на ассеты по АБСОЛЮТНОМУ
пути `/web-app/react/…` (`base` в `app/vite.config.ts` — так требует GitHub
Pages), поэтому репозиторий обязан отдаваться именно как `/web-app`. Из папки с
другим именем стенд поднимется, а приложение в iframe останется белым.

```bash
mkdir -p /tmp/pages && ln -sfn /Users/yakovpetrov/Desktop/homegrown /tmp/pages/web-app && cd /tmp/pages && python3 -m http.server 5205
```

Дальше на симуляторе (или в любом браузере):

```
http://localhost:5205/web-app/tools/stands/authcheck.html
```

Проверить другую сборку — параметром `app`:

```
…/authcheck.html?app=https://galacticstuff37-dev.github.io/web-app/react/index.html
```
(только для того же origin: iframe с другого домена читать нельзя).

На симуляторе:

```bash
xcrun simctl openurl booted "http://localhost:5205/web-app/tools/stands/authcheck.html?v=$RANDOM"
sleep 65 && xcrun simctl io booted screenshot /tmp/out.png
```

`?v=` обязателен: Safari кеширует страницу стенда. Сборку приложения стенд
каждый раз грузит с `?t=<время>`, поэтому её кеш не мешает.

## Готчи, которые стоили времени

- **Итог печатается и сверху, и снизу.** Панель Safari закрывает низ страницы, а
  скролл на симуляторе без тапа не сделать.
- **Ввод в поля приложения уезжает скроллом.** Фокус переходит в iframe, а тот
  прибит к низу страницы — Safari скроллит родителя, и итога на скриншоте не
  видно. `authcheck` в конце делает `scrollTo(0,0)` и печатает сводку по
  разделам первой: одного скриншота хватает, чтобы увидеть все разделы.
- **`<meta charset=utf-8>` обязателен**: `python3 -m http.server` не отдаёт
  кодировку, и кириллица в отчёте превращается в мусор.
- **Ввод в поля React** — только через нативный сеттер:
  `Object.getOwnPropertyDescriptor(W().HTMLInputElement.prototype,'value').set`
  плюс событие `input`. Присваивание `.value` React не замечает.
- **`el(text)` ищет по всем `[role]`**, а контейнер диалога содержит текст своих
  кнопок — для кнопок внутри диалога передавай селектор: `el('Delete it all',
  '.cf-box .btn')`.
- **Свип пропускает содержимое родителей с `overflow-x: auto|scroll|hidden`** —
  иначе карусель растений на Home даёт ложные срабатывания. Оборотная сторона:
  обрезанный по `hidden` контент детектор не покажет.
- **Детектор перекрытий не запускать для элементов ниже сгиба**: центр элемента
  попадает на таб-бар, и это читается как перекрытие.
